## 日常协作

1. **开始前先查。** 在 Issues 查看同一个 skill、同一个问题是否已经有人处理。
2. **登记优化。** 使用“Skill 优化登记”模板，说明问题和负责人；先登记，再开始改。
3. **提交改进。** 在独立修改分支上处理，发起 Pull request（修改申请），附上验证结果。
4. **统一发布。** 维护者合并已验证的改进，更新两份插件清单中的版本号和 CHANGELOG.md。
5. **更新后核对。** 员工获取已发布版本，确认 Codex 实际加载的版本。仅上传到 GitHub 不会自动更新每个人的电脑。
6. **有问题可恢复。** 保留历史记录，必要时发布回退版本。

## 编辑位置

每个技能的正式源文件在 `skills/<技能名>/`，不要编辑插件下载缓存。修改 `SKILL.md` 时同时检查该技能的 `references/`、`scripts/`、`assets/` 和 `agents/`。

本仓库提供可分发插件的目录结构；插件没有附带各业务系统的登录状态，也没有为员工自动开通业务权限。原始本机技能仍可继续使用，切换到团队版时再核对并停用重复旧副本。
