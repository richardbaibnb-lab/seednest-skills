# 入口与定位依据

以下是导航线索，每次实际任务重新核对。没有访问过的当前状态不能当作已验证事实。

## 飞书

- 民宿管理表的[（新）采购总表](https://cn06o0gh8t.feishu.cn/base/E1aBb4oCKaV51RsMVoZcNnb4n9e?table=tblZG1eOOC1JvTYs&view=vewr2po9Zt)。入口来源为已有`floor-planner/references/sources.md`，本技能创建时只读取本地记录，未访问在线表。
- 已知字段线索：采购编号、中文名、英文名、购买量、所属分类、购买进度、已下单房源、单包装物品数量、总计购买数量、备注、父记录。**到货状态的实际字段名与选项尚未验证**，运行时读取字段配置/界面，不预设ID或枚举。
- 当前视图可能过滤其他地址。按真实关联房源值/记录ID读取目标全部相关行，检查翻页、分组、折叠项和导出范围；用个人筛选或只读查询，避免改共享视图。若缺少对应字段，不私自新建字段或改表结构。
- 云盘入口：`代管房源`或`自管房源`→完整房源地址。核对管理类型、门牌、街道、suburb、州、邮编和单元号。存在冲突时先弄清，不在两个分支都建文件夹。
- 同一房源下：`setup发票`提供订单/发票依据；`setup货品照片`保存现场到货证据。用户文件夹有空格等名称差异时按实际目录与内容核实，不能误选相邻地址。
- 发票可以是图片、PDF或可读取的订单文件；本技能不继承其他流程中“仅PNG/JPG”的范围限制。不得因某份PDF不是截图就漏核对。

## Floorplanner

- 从[Floorplanner](https://floorplanner.com/)已登录账户查找本房源已完成项目。只读查验并截图，用户另行要求修改设计时再进入建模流程。
- 项目标题不足以确定版本：核对完整地址、楼层、方案内容及用户已确认记录，不假定有项目就表示模型完成。
- 本技能创建时用户的示例截图展示：`代管房源 → 26 Marianne Way, Mount Waverley, VIC 3149 → setup发票`。它只证明用户展示的目录布局，**不指定本次实际房源、群、项目或日期**；不要把此地址写入默认运行参数。

## 微信与WhatsApp

- 优先已授权连接器或受支持的已登录界面。WhatsApp网页版可作为可用时的渠道；微信渠道以当前工具能真实访问的会话为准。
- 保存实际观察到的群标识，不编链接或群ID；发送前再次检查群标题和关联房源。聊天搜索结果不等于已进入正确会话。
- 如无法读取完整历史、下载照片或发送附件，记录缺少哪一项并请用户协助相应访问；不将能力缺口伪装成自动完成，不读取私有应用数据库或绕过工具限制。

## 相关技能

- `floor-planner`：仅在用户要求补齐/修改建模时使用；其建模授权不由本技能自动扩大。
- `spreadsheets:Spreadsheets`与`pdf:pdf`：实际生成Excel及PDF时读取；先用`load_workspace_dependencies`获取当前可用运行环境。只创建本技能时无需执行真实清单导出。
- `setup-order-updater`处理购买进度和漏录商品，本技能处理现场到货，不能自动调用前者把未匹配行改成未开始或批量改已下单。
