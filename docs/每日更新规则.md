# 每日更新规则

每天北京时间（Asia/Shanghai）21:00，由维护者本机的 Codex 自动检查自制技能源文件，向本私有仓库发布实际变化。本流程同步本机文件到 GitHub；员工电脑获取更新是另一步。

## 范围与日期

- 每次动态发现本机技能目录里的自制技能，包含新增技能、说明、脚本、参考资料、图片和界面配置。
- 沿用已确认的导入范围，不复制官方系统技能、第三方插件和第三方 `detail-flow`、`reverse-engineer-anything`。
- 排除账号凭据、登录状态、运行进度、临时缓存；可疑凭据必须核实后再处理。
- 有真实变化才发布新版本。仓库首页标题使用 `Seednest 团队技能库｜最新更新：YYYY-MM-DD`，提交标题末尾使用 `｜最新更新：YYYY-MM-DD`；日期取实际发布当天的北京时间。
- 没有变化时不制造空更新、不改“最新更新日期”。

## 保留团队改动

每次比较本机版本、GitHub 当前版本及上次成功同步的本机和仓库基准：

- 只有本机变化：发布本机改进。
- 只有仓库变化：保留员工改进。
- 双方内容已经相同：无需重复上传。
- 双方修改了同一文件且内容不同：本次停止发布，保存差异并通知维护者处理，不强制覆盖。
- 本机缺少文件：保留仓库文件，不自动删除。

读取最新主分支后，以该版本为父提交；发布时再次校验主分支没有变化。主分支变化则重新比较，不能强制推送。完整验证发布结果后才推进同步基准。

## 运行与员工接入

每日任务需要维护者电脑、Codex 和 GitHub 连接可用。本机不可用时无法保证准点运行；恢复后可手动让 Codex 补跑一次。

同步只保存技能文件，不执行 Booking 回复、Wix 发文、财务、付款或其他技能业务操作，也不因同步而新增这些业务的自动任务。

员工修改前取得团队最新源文件，试用后提交修改申请，由负责人合并。插件安装缓存不是团队源文件。员工自动获取新版本尚未配置。
