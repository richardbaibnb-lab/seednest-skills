## 日常协作

1. **开始前先查。** 在 Issues 中查看同一个 skill、同一个问题是否已经有人处理。
2. **登记优化。** 使用“Skill 优化登记”模板，说明问题和负责人；先登记，再开始改。
3. **提交改进。** 在独立修改分支上处理，并发起 Pull request（修改申请），附上验证结果。
4. **统一发布。** 维护者合并通过验证的改进，更新插件版本和 CHANGELOG.md。
5. **更新后核对。** 员工获取已发布版本，并确认 Codex 实际加载的版本。下载文件、刷新插件来源和正在运行的会话使用新版本，是不同的检查点。
6. **有问题可恢复。** 保留历史版本，出现问题时由维护者发布回退版本。

## 文件与配置

共享包包含工作流程、通用脚本和必要模板。个人电脑路径、账号登录及密钥应使用各自本机配置。

迁移时核对并停用原来散发的重复旧技能，避免 Codex 同时发现多份同用途的 skill。

## 使用入口

插件安装、更新、员工接入步骤将在首次试跑后补充。当前请勿把本仓库当成已可自动同步的技能安装包。
