## 账号规则的保存方式

第一次识别并使用具体账号后，在 `references/accounts/` 下为其创建一个简洁 Markdown 文件。未使用过的账号不要预建空文件。文件名使用稳定且无敏感信息的账号代号；用页面可核对的身份信息记录其对应关系，必要时对联系方式脱敏。不要保存密码、验证码、登录令牌或会话数据。

每个账号文件只保留下次会用到的规则：

- 账号代号、用户称呼与页面可核对的身份，以及确认日期。
- 同账号参考房源链接，及哪些标题/文案特征适用。
- 命名模板、语言、品牌和段落结构。
- 用户明确确认的经营规则：如入住退房时间、适用的房屋守则、费用计算方式、取消政策、预订方式和日历策略。只保存实际确认的项目，不填写整套预设值。
- 每条规则的值、适用范围、来源日期及状态：已确认／待确认／已被替代。待确认规则不能驱动自动填写；不把平台当前默认值当作用户确认。

来源要区分用户原话、用户对建议的确认、用户手动修正、参考房源观察。用户明确要求复盘其手动修改且有同一字段前后对比证据时，可将实际变化保存为本套房源的用户修正；没有变化的默认值不在此列。用户原话或确认足以建立对应范围的经营规则，单套手动修正只更新该房源，不自动升级为账号默认。文案的非事实风格可按用户已给予的参考授权采用。

范围至少能区分：全局、账号、房源或本次操作。规则有条件时保留条件，例如“该账号同类两卧房源”；不能扩展成所有房源。用户纠正某套床型或指定某套价格，不自动改账号默认值。若用户说“以后都这样”，按其明确范围更新长期规则；范围影响其他账号且不清楚时再确认。

按当前明确指示、房源专属规则、账号规则、共享规则的顺序应用。规则过时、互相矛盾或与当前页面事实冲突时，只询问冲突项，继续其余工作。发布授权必须对应本次草稿；普通账号经营规则不能覆盖共享的草稿交付偏好。

用户未要求，不添加定时任务，不后台创建其他房源，也不把这次技能创建解释为对任意账号永久发布的许可。

## 跨任务续填

首次实际创建草稿时，在技能目录下创建 `state/listings.json`，作为轻量本地进度索引；此时才创建 state 目录。更新时保留其他房源记录，先写临时文件再替换，避免留下半份记录。

每条记录至少保留：

- 目标账号代号、包含单元号的地址匹配键，以及用户提供的地址原文。
- 图片文件夹路径、草稿/房源 ID 及链接。
- 状态：资料准备／部分草稿／草稿待确认／发布已批准／已提交审核／已上线。
- 本次工作目录、详细进度文件路径、已完成阶段、缺失项及更新时间。
- 如有发布批准，记录批准日期、对应草稿和批准范围；不可把历史批准复用于另一套房源。

详细事实表、图片与上传清单、候选文案及回读记录保存在实际任务工作目录的 `work/` 下；给用户的最终材料才进入该任务 `outputs/`。索引只保存续填所需信息，不复制照片或完整会话。若旧工作目录不可用，从草稿和原始资料重新核实，不能把本地“已填”当作页面事实。

该索引帮助定位，Airbnb 当前页面才是草稿是否存在、是否保存及是否上线的依据。并发执行同一账号同一地址时先核对已有记录，避免两个任务各建一份。
