# OPERATION-BREEZEWAY上架

## 用户约定

每个新房源的上架都从 **Basic Clean (All propertry)** 复制一个独立模板，命名后绑定新房源。用户会另行说明特殊要求，将这些要求加入对应副本。用户已明确要求执行上架时，直接完成范围内的复制、编辑和绑定，不逐步重复征求许可。

这是清洁模板配置流程，不是向 Airbnb、Booking.com 等平台发布房源。

## 开始前

- 确定目标房源的完整地址，以及用户这次提供的特殊要求、拍照要求和参考图。沿用会话中已明确的信息；仅在无法唯一匹配房源或要求存在实质歧义时询问。
- 未提出特殊要求时，保留基础模板的全部内容，继续完成复制和绑定，不自行新增房源专属要求。
- 网页默认使用 Codex 内置浏览器。用户明确选择 Chrome 或本会话已有适用授权时，遵循 `C:/Users/Administrator/.codex/skills/chrome-task-recovery/SKILL.md`，并先实际读取目标页面。浏览器初始化失败不等于网站退出登录。

## 复制并命名

1. 进入 Breezeway **Settings → Tasks → Templates**。已知列表入口为 `https://app.breezeway.io/settings/tasks/templates`；具体按钮和后续页面以当前界面为准。
2. 找到 **Basic Clean (All propertry)**。这是本账号实际使用的名称，`propertry` 为界面原有拼写。若它被改名，先在当前列表核对正确基础模板，不擅自改用另一房源的专属模板。
3. 使用页面提供的复制功能创建新副本，保留底板的清单、参考图、必拍设置和其他配置。不能直接重命名或改写底板。
4. 默认命名为 **Basic Clean (房源完整地址)**，例如 `Basic Clean (16 Gorman Drive, Mill Park, VIC 3082, Australia)`；用户指定名称时遵从用户。
5. 每个新房源使用自己的独立副本，不复用其他房源的模板。同一上架任务续做时沿用已创建的副本，避免重复复制。用户明确说“我已建好，使用这个”时，核对后使用该副本，不再新建。

## 加入特殊要求

- 只编辑目标房源的专属模板，把要求放在对应的房间或区域，例如 **Interior → Bedroom**。保持原有其他要求和设置。
- 把用户描述转成清洁人员能执行的简明要求，沿用模板主要语言。要求“每个 bedroom”时放入 Bedroom 对应清单，并核对该房源的卧室适用范围；不能只写成不限定房间的提醒。
- 用户要求“必做、必选、必须拍照”时，使用实际的 Checklist/Photo 配置及 **Photo is required** 等界面选项，并在保存后的页面核验；仅在说明里写“required”不算开启强制拍照。
- 用户提供参考图时，将原图附到对应要求的 **Reference photos**。图中如展示的是灰尘、损坏等待处理问题，说明它是问题参考，不把它描述成清洁完成标准。
- 上传权限或工具限制阻止附图时，保留已完成的文字和必拍设置，明确报告参考图未完成及具体所需操作；不要声称已经上传，也不要在未附图时留下误导性的“见附图”说明。
- 用户已经添加的正确要求应保留，避免同一条要求重复出现。

**位置约束：** 本流程在 Settings 的房源专属任务模板里修改。不能用房源 **Template modifiers → Requirements → All Cleaning** 的附加要求组代替专属模板。若本任务之前误加过这种内容，只撤回能明确归属于本任务的错误修改，保留用户原有内容。

## 实际绑定新房源

模板里写了房源地址，并不表示已经绑定。

- 在当前界面查明该房源的清洁任务如何选择模板：使用系统实际提供的模板分配或任务自动生成规则，把**目标房源**对应的清洁模板设置为刚建立的副本。不要臆造菜单、绑定入口或 API。
- 若原规则涉及多个房源，使用系统支持的房源限定规则或覆盖设置，使新房源使用专属副本，保留其他房源原有规则。核对适用范围，避免同一次清洁被重复创建为两个任务。
- 保留已有的触发时间、清洁人员、费用及其他排程条件，除非用户要求调整。
- 仅把模板列到 Property 的 Template modifiers、建立一个“0 requirements”要求组，或只在模板名称里加地址，都不能作为绑定成功的证据。
- 检查目标房源已经生成但尚未开始的清洁任务是否继承新模板；如仍使用通用底板，在系统支持且属于本次上架范围时更新为专属模板。不要改写已完成任务的历史记录，也不要创建虚假的清洁任务来测试。
- 无法找到受支持的绑定方式、缺少房源记录，或某步需要用户补充必要信息时，明确区分“模板已创建”和“绑定未完成”，继续完成不依赖该信息的工作，不能假装全部完成。

## 验收与汇报

核对以下实际结果后再报告完成：

- 新副本名称与目标房源一致，基础清洁内容保留。
- 用户特殊要求位于正确房间/区域，必拍配置生效；有参考图要求时核对附件实际存在。
- 目标房源的模板分配或自动生成规则显示使用该专属模板；有可读取的待执行任务时核对任务实际使用的模板和新增要求。
- 保存能体现结果的页面截图，简短报告房源、模板名称、特殊要求、拍照/参考图和绑定结果。把未完成事项单独说清楚。

## 本次流程来源示例

2026-10-09 用户确认的 16 Gorman 做法：专属模板 `Basic Clean (16 Gorman Drive, Mill Park, VIC 3082, Australia)` 的 **Bedroom** 下已有 `Please make sure all the window sills are wiped clean.`，并开启 **Photo is required**。当时误加的房源 All Cleaning 附加组已撤回。

这个案例用于说明正确位置和必拍方式。窗台要求不自动套用到其他新房源；其他房源只加入用户为其提出的特殊要求。案例中参考图未上传、实际任务绑定尚未验证，不能把该历史案例当作绑定流程已测试成功。
