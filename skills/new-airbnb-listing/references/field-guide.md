# 填写依据与首次缺项

这是核对指引，不是固定页面流程。只处理当前页面出现或本次房源需要的项目；具体限制、名称、可选政策与监管要求以当次平台和适用官方来源为准。

## 可以参考与必须核实的内容

| 内容 | 依据和处理 |
| --- | --- |
| 账号、房源归属 | 本次用户指定加当前账号页面验证；相似账号名称不足以确认 |
| 地址、单元号、地图 | 用户地址为主；必要时查证地址及地图，不以附近地标地址替代 |
| 房源类型、整套或独立房间 | 用户说明、明确户型/资料；外观照片不能证明客人独享范围 |
| 卧室、床型、浴室、人数 | 用户资料及可验证房源事实；不能用照片张数计算房间数，不能从床外观看尺寸或从床数直接定容量 |
| 照片 | 用户提供的本套照片；实际检查文件，识别重复角度、遮挡、无关图片和私人信息 |
| 标题 | 本次明确指示优先；默认按[双方案取名](naming-options.md)提供SEEDNEST取名及AirDNA同区域取名供用户选择，以真实卖点生成并适配页面长度，选定后再写入 |
| 简介、房源空间、房客使用权限、互动方式、其他注意事项 | 代管优先采用[19号原文模板](managed-description-standard.md)，结构措辞尽量接近；其他房源参考同账号语气。按本套事实替换，通用注意事项原样复制，不复制别套特定事实或无法兑现的承诺 |
| 设施 | 证实存在且供客人使用的设施；先逐项应用[rules.md中的已确认标配](rules.md)及[616最新51项标准](amenities-standard.md)，用户明确的通用事实无需本套照片再次证明。其他项目根据本套资料核实；看到电视不代表有流媒体订阅，看到洗衣机不代表免费或独享 |
| 停车、泳池、健身房、无障碍 | 核实权限、费用、位置、开放条件等适用事实；照片或同栋设施不能证明可用 |
| 周边描述与交通 | 地点信息要与真实地址相符；若使用距离或时长，查证位置、交通方式及依据，不照抄别的房源 |
| 安全设备、摄像设备及其他披露 | 使用用户明确资料及适用页面说明；没有照片不是不存在，不把别的房源披露复制过来 |
| 房屋守则、入住退房时间、入住方法 | 本套指定值或已确认的适用账号规则；门禁密码等私密信息不写公开介绍 |
| 币种、基础房价、周末价、清洁费、额外人数费、折扣 | 使用本次明确设置或可适用的已确认计算规则；其他房源价格只作建议依据，检查平台自动促销 |
| 开放日期、最少及最多入住天数、准备时间、提前预订 | 使用用户明确安排或已确认的适用规则；不能把未知当作“全年开放” |
| 即时预订、房客要求、取消政策 | 使用已确认且当前可用的选项；新选项和冲突项再问，不盲目接受推荐设置 |
| 登记、许可、税务或身份声明 | 仅填写用户提供或可验证的资料；遇到适用性问题查当前官方说明，不猜测或代作未知真实性声明 |

## 首次沟通如何收敛

先看文件和同账号参考房源，再问真正无法确定的内容。实际需要时可分为三组，合并提问，不把全部问题机械发给用户：

1. 本套事实：房源类型与使用范围、卧室及床型、浴室、最多人数、不能从照片证实的重要设施或限制。
2. 本套经营设置：币种与价格/费用、可入住起始日、开放范围，以及账号没有已确认规则的预订设置。
3. 可复用规则：从参考房源提取的语言、标题结构、文案段落及确实希望以后沿用的服务与经营设置。

说明每项来自用户资料、图片可见事实、参考房源观察还是待确认建议。不要让用户确认整批未经阅读的默认值。只有当前步骤确实需要的信息才阻挡该步骤；其余内容继续推进。

## 草稿回读重点

- 房源属于正确账号，地址及单元号正确，地图位置与地址一致。
- 上传预览与图片清单匹配，封面、顺序和空间归类正确，失败或重复图片已处理。
- 逐个卧室检查组内第一张能看到完整床，细节特写放后面；该要求独立于整套房源封面。
- 逐项核对用户确认的标配设施清单，不能只检查最初向导展示的设施；Cot常备、入住期间清洁额外收费的详情也要保存并回读。
- 标题符合本次规则；介绍中的每项具体事实有依据，无残留其他房源名称、地址或独有设施。
- 人数、卧室、床位、浴室和设施跨页面一致；没有为通过校验临时填写的虚构数据。
- 户外空间逐项核对Patio、BBQ和Outdoor dining area，不因为已选BBQ就漏看另外两项；是否适用以本套照片、用户资料或用户手动修正为准。
- 费用、币种、优惠、日历和预订条件已回读，平台自动启用的选项符合用户规则。
- 页面已保存且仍是草稿。若必须发布后才能设置某些项目，明确列为后续项，不把它们报告成已完成。
- 审阅摘要提供账号、房源地址、标题、草稿链接、影响费用或接单的主要设置，以及尚缺内容，便于用户对具体草稿作决定。

## 2026-09-17 首次实际执行观察

- 当次网页先搜索地址并确认单元号，再创建有ID的草稿；草稿新建后立即记录ID。房源管理页的新建按钮未响应时，可通过页面实际提供的 Airbnb your home → Get started → Create a new listing 入口继续，不反复点击新建。
- 当次基础页先填总人数、卧室数、床数和浴室数，床型稍后补充。保存退出后再次打开可能跳到后续页；这不证明上一页的默认值已被用户确认，必须按事实表回读纠正。
- 照片操作为 Add photos → Browse → 选择本地文件 → Upload。文件选择数与实际上传成功数不同，上传后还需核对预览、封面和顺序。
- 这些是一次页面观察，不是永久固定流程；后续以实际界面为准。
- 页面刚打开时照片可能短暂显示空上传页，地图也可能未加载完整。等待照片组、既有标题或字段等已知内容出现后再比较，不把加载中的空页面当成用户删除内容。
