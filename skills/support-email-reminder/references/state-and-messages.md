## 状态字段

- 顶层保存 `schema_version`、`mailbox`、`timezone`、`monitor_from`、`last_successful_scan_at`、`last_run_at`、`recipient`、`items`、`last_blocker`。时间用带时区的 ISO 8601，消息里转换为墨尔本时间。
- `recipient` 保存核实的姓名、外部标记、头像、历史依据，实际发现稳定会话 ID 后才补充。
- `items` 以“邮箱 + 会话/邮件 ID + 本轮客人来信 ID”为键；没有稳定 ID 时使用发件邮箱、原始主题、精确时间及必要正文摘要组合，不能仅按主题去重。
- 每项保存客人/发件邮箱、主题、来信时间、问题摘要、实际邮件定位信息、本轮状态 pending/replied/uncertain、最后核实时间、回复证据、首次/二次提醒各自的发送状态及证据。
- 每次提醒保存 `delivery_status`（not_sent/sending/confirmed/unknown/failed）、`attempted_at`、`confirmed_at`、消息文字或可核验摘要。发送前写 sending；只有工具确认成功或聊天中出现对应消息才能写 confirmed。重启发现 sending/unknown 时先核对聊天，不盲目重发。
- 合并消息的证据关联到每个咨询，各项独立维护回复及二次提醒，不能因一项已回复而关闭整批。新问题开启新一轮，保留旧轮历史。
- 临时文件加原子替换保存，两个阶段串行写入；若已有运行仍在进行，先协调完成，不并发改同一状态。不要存密码/令牌。
