# OPERATION-周四发票录入

把用户原来在网易邮箱大师 AI 中执行的周四账单整理流程固化为可迁移的本地归档技能。用户说“运行周四任务”或“执行 OPERATION-周四发票录入”时，按以下规则执行，不必再让用户粘贴 SOP。

## 时间与保存位置

- 默认处理最近一个已经结束的完整周期：上周四 09:00 至本周四 09:00，**固定 UTC+10:00**。采用开始时间包含、结束时间不包含的区间 `[start, end)`，避免相邻周重复；恰好结束时刻收到的邮件归下一周。
- 不自动改成墨尔本夏令时，也不按电脑本地时区解释 09:00。中国标准时间对应周四 07:00。按邮件实际接收时间归期，不按发票日期、邮件发送时间或下载时间。
- 非周四执行时，以最近一个已到达的周四 09:00 为截止点；周四 09:00 前，默认仍处理上一完整周期。用户指定日期/补跑周期时以其要求为准；若要求未结束的本周，明确为截至当前的部分扫描，不能宣称整周完成。
- 每次开始时简短说明实际起止时间、时区及目标路径。跨邮箱的界面时间可能不同，先核对显示时区再筛选；必要时宽搜前后一天，再按真实时间精筛。不清楚边界邮件时间时记录待核实。
- 保存到当前用户实际的 `Downloads/周度invoice更新/YYYY.MM.DD - YYYY.MM.DD/`，两端日期分别取 start/end 在 UTC+10 的日期。Windows 优先解析系统 Downloads 已知目录或其重定向路径，未设置时才用当前用户的 `Downloads`。**不硬编码旧电脑的 `C:\Users\Owner`，也不硬编码创建本技能时的用户名。** 用户已指定新路径时沿用。
- 使用 [scripts/prepare_week.py](scripts/prepare_week.py) 可计算周期并解析 Downloads；默认只输出计划，增加 `--create` 才建立目录。可用 `--week-ending YYYY-MM-DD` 指定已结束的周四；`--downloads` 指向 Downloads 基目录。脚本只准备本地目录，不检查邮箱、不下载附件、不证明任务完成。没有 Python 时可按同一规则直接操作，无需为了本技能安装运行时。

## 邮箱访问与扫描

1. 先确定当次环境实际可用的邮箱访问方式。用户原工作环境是网易邮箱大师；若有可用的桌面控制，按该工具/技能的当前说明操作。也可使用已授权、已登录的邮件连接器或对应网页版。使用浏览器/桌面功能前读取相关控制技能，不能将本机曾经登录过视为当前可访问。
2. 对每个访问入口核实其覆盖的账号；连接一个 Gmail 不等于覆盖全部七个邮箱。不要为这项任务更改转发规则、申请额外邮箱权限或读取客户端私有数据库、密码及令牌。
3. 刷新后扫描区间内收件箱的全部来信，包含已读和未读，展开分页/继续加载直到覆盖完整区间。按每封来信核对时间，不能将会话里区间外的旧附件当成本周新账单。
4. 至少做两轮：第一轮查 PDF 附件；第二轮检查正文图片、内联附件及账单相关内容。不能只用“有附件”、`has:attachment`、文件后缀或主题关键词过滤，因为纯内联图片可能没有回形针。检索只是缩小范围，完成判断依赖整段收件箱覆盖及正文检查。
5. 个别账号无法登录或无法完整加载时，继续处理可访问账号，记录缺失账号与未查范围。仅在确实需要时请用户登录/补充入口，不能把访问失败记作“0 张”。没有可用入口时保留已准备的目录和进度，报告尚未扫描，不声称已经执行完。

## 收集与排除规则

- 收集范围是区间内收到、仍在收件箱中的邮件：下载其 PDF 附件，以及服务商开具的账单类图片，包括 `invoice`、`tax invoice`、`statement`、`quote`。不要把后续飞书核对的“只接受正式发票”规则套到这里；statement 和 quote 在本地收集阶段可以保留。
- 对图片必须打开查看，确认图上是账单/报价及可辨认的供应商、服务项目、金额等信息。只凭文件名、主题或“内联图片”标记不足以确认。PDF 同样打开检查可读性和是否命中明确排除项；无法辨认的候选保留来源并标注待核实。
- 排除零售/超市小票，例如 Kmart、Coles；工作或现场照片；公司 logo、签名图、广告图、追踪图；没有附件或账单图片的付款提醒。账单邮件同时带现场照时只保存合格文档。
- 普通正文文字及付款链接不能冒充原始附件。仅有链接、原图无法下载或受密码保护等情况记录为待处理，不把网页截图、缩略图或空白 PDF 报告成已下载原件。
- 优先下载原始 PDF/图片。内联图使用可用的“保存图片”、查看原图或原始 MIME 附件读取能力；只提供低清预览时先寻找原图。确实只能截图时保留为有说明的临时核对证据，并明确原件下载未完成。

## 下载、续跑与核验

1. 建立本周根目录及七个子目录；存在时复用，不清空旧文件。先读取已有汇总及文件，续跑仍需补扫缺失的邮件范围。
2. 逐一下载候选并打开确认，再放入收件邮箱对应目录。若浏览器先下载到默认位置，仅移动本轮新下载、来源可核实的文件，不整理其他下载内容。
3. 尽量保留原文件名。同名不同内容时加收件日期、短邮件标识或序号，不能覆盖。没有文件名的内联图使用收件日期、发件人和图片序号，并根据真实文件格式保留扩展名。
4. 在同一邮箱目录内，用邮件标识、附件标识及文件内容/hash 识别重复。相同文件的重复来信可以复用已有文件，但清单保留全部来源。同名、同金额不能证明重复；修订账单内容不同就保留。相同内容进入不同目标邮箱时，保留各自目录的归属并记录重复线索，不擅自跨邮箱合并。
5. 周目录根部维护 UTF-8 `归档清单.csv`，记录：收件邮箱、接收时间（含时区）、发件人、主题、可用的邮件ID/链接或定位信息、原文件名/内联序号、文档类型、保存的相对路径、文件大小/hash、状态、原因。不记录登录凭据。对排除项保留可追溯的原因；续跑更新同一来源项而非不断追加重复行。
6. 检查七个目录名称齐全；已保存项都对应实际存在、非零且可打开的文件；下载临时文件不计入完成；目录中的本轮文档都能追溯来源。核对清单与磁盘数量，区分邮件数、文件数和重复来源数。
7. 根部保存简短 `执行汇总.md`，注明区间/时区、实际路径、每邮箱扫描状态和 PDF/图片数量、排除及重复情况、Maria/Damien 检查结果、待处理项。已有汇总更新时保留先前执行信息，不因本轮部分成功抹掉未完成事项。

只有全部七个邮箱的区间扫描、内联图查漏及文件核验完成，才能报告“本周期已完成”。存在未扫描账号、未检查图片或未成功下载候选时报告“部分完成”，给出已完成数量和具体剩余事项；不以目录已经建立作为完成证据。

## 输出与迁移边界

- 回复用户实际归档周期、目标路径、各邮箱 PDF/图片数量、两位必查发件人的结果，以及任何未完成项。用户有需要时给出报告链接；若当前环境只允许展示 outputs 内的文件链接，将汇总制作为可核验的输出副本，保留真实归档位置。
- 本技能的“录入”按用户原 SOP 指本地收集归档。调用它不自动授权付款、发邮件、转发账单、修改邮件分类/删除邮件，或写入飞书、QuickBooks；后续核对/入账仅在用户要求时接续对应流程。
- 本技能默认按用户手动调用执行，不因名称含“周四”就创建定时任务。用户另外要求自动运行/提醒时，使用当前平台的自动化工具并明确固定 UTC+10 的时间规则；不恢复旧电脑的 VBS 任务，也不暗示该任务已存在。
- 换电脑需要迁移/安装整个技能目录（包括 scripts 和 agents），在新环境核实七个邮箱的实际访问，再解析新 Downloads。旧账单归档和定时任务是独立内容，不假定随邮箱账号或 skill 自动同步；仅在用户要求时迁移。
