# SALES-STR Report 收入报告制作

在用户的 Qwilr 账号中完成可验收的房源短租收入报告。以当次房源资料、最新 AirDNA 数据和用户选定品牌及语言的现有 sample 为依据，保留所选模板的品牌、版式与章节逻辑。

## 模板保真与客户报告要求

- 用户明确要求：每次只根据地址替换相关数字、地址、日期、房源图片，以及确需随物业或地区变化的文字。**原 sample 的章节顺序、段落形式、折叠栏目、计算器、图片位置、字体、字号、字重、颜色、对齐和间距均保持不变。**不得擅自删减、重排、改成新的平铺结构或重写通用销售文案。
- 在原文本位置小范围替换，图片使用原图片框的替换功能。不要清空整块后粘贴新 HTML/Markdown，也不要因为操作方便删除折叠栏目或计算器。发现误改格式时，用原 sample 的原生格式复制恢复受影响内容，再逐项替换；复制后核对每个栏目和图片数量，避免末尾图片遗漏。
- **客户报告中不要提 AirDNA**，也不新增数据来源说明、账号信息、内部筛选过程、模板修复解释或审核笔记。研究来源、原始数据和查询时间只保存在内部工作记录。数据截图可裁去网站品牌与无关导航，但保留真实数字、表头、单位、月份和图例。
- 原有通用服务、管理/营销费用比例和业务条款不因更换地址而改写；Cleaning Fee 中的房间范围与单次清洁费区间须按第 3 节每次更新。发现其他费用疑点，在报告外单独反馈，不借此改变结构或新增说明段落；数字计算须清楚沿用的口径，不能把毛收入误写为净收益。
- 验收前与原 sample 逐块对照段落、折叠栏目、计算器及文字样式，不能只检查内容正确或页面能打开。
- Qwilr 原生复制可能遗漏局部字号、居中和折叠栏配色；格式复制操作也可能未实际生效。每次以重新读取的段落类型和实际预览确认，不能仅凭点击成功判断。修复时保留原段落，使用文字工具恢复原字体/字号/对齐；核对展开内容的格式。
- 计算器的预览滑杆值不等于保存的默认值；在滑杆 Edit 中更新 Initial value，再重新打开独立预览确认默认入住率和结果都正确。
- 2026-10-05 用户再次确认：截图指出的市场说明、Seasonal Trends 和地图必须参考原 sample。市场比较段不额外插入目标房源的日价/入住率、年度总收入或清洁费拆分；保留原有段落逻辑，只替换有依据的物业相关内容。Seasonal Trends 使用原模板的 **12 个月日历热力图**，不得自行改成折线图；正文保持原模板的简短形式，仅更新真实指标、房间范围与季节结论。地图使用原模板的 **区域范围＋房源图钉** 构图，隐藏地址详情侧栏和无关操作界面，不能用带商家/地址卡片的近景地图替代。验收须比较图片类型和正文语义，不能只比较字体与元素数量。

## 1. 确认房源与本次资料

1. 记录完整地址（含 unit、suburb、州、邮编）、报告语言、报告日期，以及房源类型、实际卧室数、浴室数、计划入住人数、已知床型/沙发床方案。
2. 优先采用用户提供的房源资料；缺失时查询 **realestate.com.au** 的同地址页面，核对单元号和地址。用户原文中的 realesate.com 指此澳洲房产网站。不要拿同楼不同户或附近同名街道代替。
3. 房产网站可确认实际房型，但通常不能证明短租入住人数。人数根据用户提供或已确认的床位方案确定；确实无法判断时只询问必要的缺失项，不能直接接受 Rentalizer 的默认人数。
4. 建立本次工作记录，保存在当前任务可写目录，例如 `outputs/str-report/<address-slug>-<date>/`，不用技能目录存客户报告，也不写只读项目资料。记录来源链接、查询时间、配置、筛选、可比房源、数据、截图路径、Qwilr 原模板与副本链接、已完成章节及待核实项，方便中断后继续。

### 长租信息：每次查询，仅在完成回复中汇报

- 每份 STR 报告都查询同地址的长租周租，优先读取 realestate.com.au 的 Rental income／Estimated income；区分网站估值、挂牌租金和历史成交租金，记录来源、更新日期及区间（如有）。没有可靠值时如实说明，不能编造。
- 以 **周租 × 52** 折算年租，注明为未扣空置及费用的年度毛租金参考，不把估值称为已签约租金或业主净收益。网站仍使用改造前房型时，在完成回复中简短提示，不能自行加价当成网站结论。
- 长租金额和比较只保存在内部工作记录，并在最终交付回复中随每套 Qwilr 链接列出 **AUD 每周金额、AUD 每年金额、估值/挂牌等口径及必要的来源链接**；不写入 Qwilr 客户报告、正文、计算器、图片或客户报告附件。

## 2. 复制正确的 Qwilr 模板

1. 打开用户 Qwilr 账号，进入 **Pages → STR REPORT → Sample**，按当次已确认的 ARG／我们的品牌选择查找模板；若品牌模板位于其他文件夹，通过实际页面定位并记录。
2. 我们的模板：中文复制 **chinese sample**；英文复制 **english sample**。若英文模板实际仍名为 **sample**（用户截图如此），先打开确认正文为英文，再作为英文模板使用。ARG 模板：查找 ARG 对应 sample，打开确认品牌和正文语言后再复制，不用我们的模板替代。存在多个无法辨认的候选时才请用户指定。品牌素材、服务文案、费用比例和条款沿用所选 sample；若与下文固定计算口径不一致，先核对并向用户确认差异，不能直接将 SEEDNEST 口径套入 ARG。
3. 先复制，再把**新副本**移到 **STR REPORT → prepare**。记录副本链接/页面 ID；不要编辑或移动 Sample 中的原件。重试或恢复任务时先检查已有本次副本，避免重复创建。
4. 将左上角页面名称改为本次完整地址；同地址多版本时按现有命名习惯区分语言/日期。核对副本的发布状态，使用草稿/内部编辑预览交付；若复制继承 Live，先将新副本设为可编辑草稿，不修改原件状态。
5. **先从头到尾查看完整模板**，列出所有章节、旧地址/地区、日期、房源照片、数据截图、金额和地址相关文案，再逐项替换。16 张参考截图只展示部分流程，不代表模板只有这些章节。

## 3. 房源图片、地址与文案

- **长期照片来源规则（用户于 2026-10-15 再次明确）：只要用户没有提供照片，每次先使用 realestate.com.au 同地址房源的真实照片，不重复询问照片来源。** 用户提供照片时优先使用用户照片，不足部分再用同地址网站照片补齐。进入已核对同地址的完整图库选择实景图并记录来源，不能仅因没有业主照片就留下“待补充”占位图或要求用户上传。网站照片仍须核实同一房源，不能用附近房源或生成图替代。只有图库确实无法访问或缺图时，才如实说明具体缺口。浏览器遵循最新全局 AGENTS.md；用户于 2026-10-15 已改为默认 Chrome，无需逐次询问，并先执行 chrome-task-recovery 流程。
- 选择 **6–7 张**，尽量覆盖客厅、厨房/餐厅、主要卧室、浴室及其他主要区域，并包含 **1 张建筑外观**。优先清晰且互补的照片，不为凑数重复图片。确实找不到足够的同房源照片时如实记录缺口，不用别的房子或生成图替代。
- 同步更新封面房源背景、图片章节标题和正文图片。保留通用品牌素材，替换所有属于旧房源的照片。
- 换图后必须检查原图片框继承的 Crop/Zoom。旧 sample 的 1.5–2.25 倍放大会把新房间裁成局部并降低清晰度；保留原框尺寸、位置和比例，按新图重置为完整画面（通常 Zoom=1），逐张预览。选择能看清房间布局的照片，不只展示床角、台盆或窗户。
- 优先从同房源完整图库取得大图，建议宽度至少 1200 像素且不低于实际展示宽度；不要把 720 像素缩略图放大后当高清图。检查上传后的实际分辨率、裁切和预览，不能仅凭上传成功验收。
- 全面更新左上角页面名称、封面地址、正文标题、地区/周边描述、地图、图片中的地址、图注和结尾等与房源有关的位置。嵌在截图里的旧文字须换图，不能只改可编辑文本。
- 更新为本次制作日期；默认取用户所在时区的当日日期，按模板精度显示。英文月/年沿用如 `September, 2026` 的样式，中文使用相应年月。不是固定使用示例日期。
- 根据已核实的新地址和物业特点重写相关描述。不要只替换 suburb 而留下旧区域设施、距离、交通和市场结论。通用服务说明和品牌信息按模板保留。

### 报告的房间范围规则

| 实际卧室数 N | 报告推荐范围/可比卧室范围 |
| --- | --- |
| 1 | 1 房，不扩成 1–2 |
| 2 | 2–3 房 |
| 3 | 3–4 房 |
| 4 | 4–5 房 |
| 5 | 5–6 房 |
| N ≥ 2 | N–(N+1) 房 |

依用户规则，额外一档体现可放沙发床的运营方案。按所选语言更新 Surrounding Comparison 等章节，并在合适位置简短说明沙发床方案，区分实际独立卧室和拓展住宿安排。**不要因此把 Rentalizer 的实际 Bedrooms 自动填成 N+1，也不要把 Bedrooms 当作床的张数。**

### 每次更新单次清洁费区间

Cleaning Fee 章节的房型标签和金额每份报告都要随报告房间范围更新，在原位置保留原加粗、字号和段落形式；不能把 sample 的 `3-4 bed properties : $300` 当成固定通用文案。按用户确认的 AUD 区间填写：

| 报告房间范围 | 单次清洁费区间 | 英文展示 |
| --- | --- | --- |
| 2–3 房 | AUD $180–$280 | `2–3 bed properties: $180–$280` |
| 3–4 房 | AUD $200–$300 | `3–4 bed properties: $200–$300` |
| 4–5 房 | AUD $260–$360 | `4–5 bed properties: $260–$360` |

中文报告使用同一档金额，按原中文模板表述。其他房间范围需用户确认金额，不自行外推。本表为客人每次住宿支付的单次清洁费展示区间；年度收入公式与计算器中的年清洁费仍取同一次最终预测，不用此区间或其中点直接替代年清洁费。

## 4. AirDNA Rentalizer 与可比房源

### 4.1 设置目标房源

1. 在 **Rentalizer → Search address** 输入完整地址并选对结果，确认 unit、suburb、地图位置等。
2. 设置正确的 **Bed（实际卧室）、Bath、Guests**，点击 **Update**，等结果刷新后复核这三项和地址。浴室保留来源中可确认的小数值。
3. 点击 **Edit Comps**。默认列表与首次显示的预测不是最终结果。

### 4.2 在 Manage Comps 筛选

在右侧逐项设置并 **Apply**；完成后重新打开检查实际选中值，不只依赖 “4 applied”等计数。

| 筛选 | 规则 |
| --- | --- |
| Core Attributes → Accommodates | 按已确认的计划人数和沙发床容量设置相近人数区间，记录上下限。用户截图的 4–5 房示例为 8–10+ 人，不是所有房源的固定值；其他房型不能无依据套用。 |
| Core Attributes → Bedrooms | 1 房选 1–1；N ≥ 2 选 N–(N+1)，与报告推荐范围一致。 |
| Listing Type | **Entire Place**，不是 View All、Private Room 或 Shared Room。 |
| Real Estate Type：Apartment | 选择 **Apartment**。 |
| Real Estate Type：House | 同时选择 **B&B、House、Unique**。不要只勾 House。 |
| Performance → Days Available | 只选 **271–365** 天，点击 Apply。此项是可供预订天数，不是入住天数或入住率。 |

若房源为 townhouse 等且分类不明确，先依据实际房产类型判断；无法归类再询问。不要为了增加样本擅自变成 View All，也不额外套用用户未指定的评级、设施或高价筛选。

### 4.3 清理默认列表、添加合适样本

1. **移除 My Comps 中最开始的全部默认 listings**。筛选 Available Comps 不会自动清理 My Comps；看见旧房型仍留在上面时不能直接更新报告。这里的删除仅移出当前可比集合，不是删除平台真实房源。
2. 在 **Available Comps** 审查符合条件的条目。**每一套候选房源在点击＋移入上方 My Comps 池前，必须先点开详情和照片，查看实际房屋样子及质量**；不能只凭列表数字、名称、封面缩略图或收入排序入池。重点比较建筑与装修底子、空间和采光、厨房/浴室档次、家具软装、维护状况及泳池/景观等明显溢价条件，再综合距离、房型、浴室、容量和运营可比性，只选择与目标房源接近的样本。查看主要客厅、厨房/浴室和卧室图片；详情看不全或照片不可用的候选暂不入池，记录缺口。
   - 目标房源为空房时，在真实房屋底子上，按 **Seednest 平时实际布置后的效果** 判断成品档次，不因空房低估，也不假定普通软装可把老旧厨卫、空间或建筑条件升级成豪宅。优先参考用户提供的 Seednest 成品图、可核验历史案例及本次已确认的布置方案；缺少足够参考时记录具体假设，不冒称已确认的装修水平。
   - 每套候选在内部记录名称/链接、看过的照片区域、与目标的相似点和差异、纳入或排除理由；不把内部筛选过程写进客户报告。不得只挑最高收入，也不得为了凑数纳入明显更豪华、设施溢价或底子不同的房源。加入当前合理本地区域内全部符合条件且合适的条目；5–6 个是最低目标，不是最多只选 6 个。
3. 目标至少 **5–6 个**合适 comps，争取 6 个或更多；5 个仍可使用并报告实际数量。少于 5 个时，点地图右下角 **−** 先 1–2 次，每次等地图和列表刷新，再检查新增结果并添加。
4. “−”表示缩小地图比例尺、**扩大搜索地理范围**。保留筛选条件，优先同 suburb 或相邻且可比的区域；必要时继续合理扩大并记录涉及区域。不能无限扩到无关市场来凑数。合理扩大后仍不足 5 个，保留真实数量、说明样本不足，不偷偷放宽房型/271–365 天条件，不把不足样本写成充分结论。
5. 核对最终 My Comps 每行和数量：Bedrooms、Bath、Accommodates、Days Available、区域、ADR、Occupancy、Revenue Potential、Revenue（页面有时需横向滚动），以及可见名称/链接。排除重复和不匹配条目并记录理由。
6. 点击 **Update Report**；等待返回 Rentalizer 且指标更新。复核目标地址、Bed/Bath/Guests、最终列表和数量。若返回后配置错误，先纠正并重新核对/更新可比集合，再取数截图。

### 收入计算：严格保留模板的按天公式

- 用户已明确：第一行 **71% 是扣除费用后的业主收入比例**，不是入住率；第二行必须使用本房源实际预测入住率折算的入住天数。不要把第二行改为“年收入 × 71%”，也不要把两个百分比混用。
- 保留模板两行计算结构和字体：第一行 `日均金额 A × 71% = 扣费后每日金额`；第二行 `扣费后每日金额 × 全年入住天数（本房源入住率）− 年清洁费 − 模板软件费 = 年净额`。全年入住天数为 `365 × 入住率`，计算中保留精度，最终金额才四舍五入。
- 日均金额、清洁费、入住率取同一次最终预测。按用户指定先按日金额与天数计算、再扣清洁费；不要先从年收入扣清洁费再反推 accommodation-only 日价后又扣一次。不要沿用上一套物业的费额或预测。
- 同步正文日价、两行公式、净额标题的区间下限和原生计算器。计算器若使用原模板变量，核对 `A × 365 × occupancy / 100 × D − L − M`，其中 D=0.71、L=年清洁费、M=模板软件费；保存正确的 occupancy Initial value，再独立预览核算。
- 2026-10-12 用户明确：**每份报告的“预计年度净收益”金额整行必须加粗，包含“约”、区间上下限、澳元及 AUD；并展示基准测算值至上浮几千澳元的区间**。这是对原 sample 字重保真规则的明确例外，其他字号、颜色、对齐和位置仍沿用模板。
- 区间下限为上述公式的真实基准净额（按原展示精度取整）；上限为优化运营情景，通常较基准高数千澳元，优先采用用户当次指定值，否则结合合理日价或入住率提升测算并适度取整。在现有金额说明处简短写清“下限为基准测算，上限为优化运营情景”，不把上限当成原始数据平台预测或保证收益，也不为了区间而改高基准公式或计算器默认值。内部记录上限的假设和反算依据。用户本次 Durack 示例为 43,248–50,000 澳元，仅适用于该报告，不能固定套用其他房源。
- 用户明确要求调整入住率以达到某个收入目标时，可在保留日价和既定费用的前提下反算入住率，使用合理精度并同步正文、公式、净额标题和计算器 Initial value。在原有入住率位置简短标为目标/情景假设，不能把调整后的目标当成数据平台原始预测；原始预测和用户授权记录留在内部工作记录。不得把某次目标金额或入住率推广为以后所有报告的默认值。
- 2026-09-20 用户确认的 30A 示例仅用于理解：517 × 71%=367.07；36% 对应 131.4 天；367.07 × 131.4 − 9,188 − 1,440=37,605（约数）。这些金额和入住率不是其他房源的默认值。
